# Native Customer–Orders–Lineitem merged index

This standalone library supplies the concrete Customer–Orders–Lineitem (COL) definition for DBSP's general merged-index module, `dbsp::trace::merged_index`. It also holds the Q3 readers that the reconstructed circuit uses.

The folded-key encoding (11, 20, and 25 bytes), the payload types, and the batch and file layout are specified in [col-storage.md](../../../docs/design/merged-index/col-storage.md). The definition is generated by the SQL compiler from `col.mi` into the committed `src/generated.rs`, which the crate root re-exports: the key and payload types, `CustomerOrdersLineitemDefinition` with typed fold and unfold, the prefix functions, and the payload codec. `lib.rs` adds only `build_batch`. Regenerate with `generate.sh`; do not edit `generated.rs` by hand.

Commands live in [WORKFLOW.md](../../../docs/design/merged-index/WORKFLOW.md). The library's own suite runs with `cargo +1.96.1 test --offline --locked` from this directory. It covers encoding, payload validation, batch consolidation, cursor seeks, layer files, native spine compaction, snapshots, and reopened files. This experiment does not migrate files written with an earlier payload codec.

## Q3 readers

The `q3` module reconstructs the four native accumulated reads from COL snapshots that the harness maintains outside the circuit. The harness-side `ManualIndex` (in [`q3-ivm-baseline`](../q3-ivm-baseline/README.md)) appends to the index; this library never does. `q3.rs` contains no insertion call.

`Q3State::publish` supplies one transaction's `Old` snapshot and its `Dlt` run. `Q3State::collect` then reads `Dlt` once (`capture`: the touched customers, the driving deltas `ΔC`, `ΔO`, and `ΔL`, and each reader's requests) and runs one scan session over the touched customers' groups of `Old`. The harness takes the driving deltas through `take_driving_deltas`, which moves them out, and hands them to the view circuit's input handles. Call `Q3State::finish` after the transaction commits and before publishing another; it releases the readers and returns the session's reads. [reconstruction.md](../../../docs/design/merged-index/reconstruction.md) gives the full transaction contract. Every delta row must carry its trie keys, which the harness's `reconstruction::prepare` ensures for any change of the base tables.

Each of the four readers holds the request prefixes of its driving delta and keeps only the rows it requests (the deltas are built once into the hand-off structure and borrowed by the routing) (dbsp's `merged_index::reader`; decision of 2026-11-12). The result types are named `*Vector` (`CustomerByCustkeyVector`, `OrdersByCustkeyVector`, `JoinedByCustkeyOrderkeyVector`, `LineitemByCustkeyOrderkeyVector`):

| Reader | Method | Requests of | Keeps |
| --- | --- | --- | --- |
| `CustomersAfter` (`C⁺`) | `customers_after` | `ΔO` | `Old`'s customer and `ΔC`'s rows, consolidated, of the customers of `ΔO` |
| `OrdersBefore` (`O⁻`) | `orders_before` | `ΔC` | the orders of each customer in `ΔC`, before |
| `JoinedAfter` (`J⁺`) | `joined_orders_after` | `ΔL` | `J`'s rows at the `(custkey, orderkey)` of `ΔL`, built at routing |
| `LineitemsBefore` (`L⁻`) | `lineitems_before` | `ΔJ`, as requests | the lines of each order where `ΔJ` has a row, before |

The folded keys put a customer first, then each order followed by its lines, so one forward pass over a group knows both terms of `ΔJ = ΔO ⋈ C⁺ + O⁻ ⋈ ΔC` before an order's lines arrive. The generic `route` keeps the stored readers' entries (a payload is read and decoded only for an entry that some reader keeps); the Q3 hook in `q3.rs` adds the customer and order steps that build `J⁺`'s rows and decide, exactly, where `ΔJ` has a row. `ΔJ` is a request set only: the circuit computes its own. A partner read checks that each key of its delta is one of its reader's requests and errors otherwise.

The join readers (`join_orders_customers`, `join_lineitems_orders`) call `expect` on reader errors. A request outside a reader's requests therefore panics the worker; `reconstruction::prepare` makes `Dlt` complete, so a harness-fed change never makes one. A join with a snapshot reader lets its delta drive and counts its reads of the readers' batches under the `requested_slice` read owner.

`verify.sh` in the Q3 experiment runs both generated circuit modes over the same loading and RF1/RF2 transactions and checks reader rows, emitted deltas, and materialized `V` against a full join recomputed from the logical records. It also compares the two modes' per-transaction JSON output byte for byte. The COL weighted-reader, storage, and compaction tests stay in this library's suite.
