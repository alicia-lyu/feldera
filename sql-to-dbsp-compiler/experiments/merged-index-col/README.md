# Native Customer–Orders–Lineitem merged index

This standalone library supplies the concrete Customer–Orders–Lineitem (COL) definition for DBSP's general merged-index module, `dbsp::trace::merged_index`. It also holds the Q3 readers that the reconstructed circuit uses.

The folded-key encoding (11, 20, and 25 bytes), the payload types, and the batch and file layout are specified in [col-storage.md](../../../docs/design/merged-index/col-storage.md). The definition is generated by the SQL compiler from `col.mi` into the committed `src/generated.rs`, which the crate root re-exports: the key and payload types, `CustomerOrdersLineitemDefinition` with typed fold and unfold, the prefix functions, and the payload codec. `lib.rs` adds only `build_batch`. Regenerate with `generate.sh`; do not edit `generated.rs` by hand.

Commands live in [WORKFLOW.md](../../../docs/design/merged-index/WORKFLOW.md). The library's own suite runs with `cargo +1.96.1 test --offline --locked` from this directory. It covers encoding, payload validation, batch consolidation, cursor seeks, layer files, native spine compaction, snapshots, and reopened files. This experiment does not migrate files written with an earlier payload codec.

## Q3 readers

The `q3` module reconstructs the four native accumulated reads from COL snapshots that the harness maintains outside the circuit. The harness-side `ManualIndex` (in [`q3-ivm-baseline`](../q3-ivm-baseline/README.md)) appends to the index; this library never does. `q3.rs` contains no insertion call.

`Q3State::publish` supplies one transaction's `Old` snapshot and its `Dlt` run. `Q3State::collect` then runs one scan session and fills four typed readers (dbsp's `merged_index::reader`). The harness takes the driving deltas, the readers' `Dlt` batches, through `take_driving_deltas` and hands them to the view circuit's input handles. Call `Q3State::finish` after the transaction commits and before publishing another; it releases the readers and returns the session's reads. [reconstruction.md](../../../docs/design/merged-index/reconstruction.md) gives the full transaction contract. Every delta row must carry its trie keys, which the harness's `reconstruction::prepare` ensures for any change of the base tables.

Collection projects each entry of a touched customer's group, once, into the typed rows of every reader of its stream. A reader holds two batches, `Old`'s and `Dlt`'s; the before reads take `Old`'s, and the after reads take both in one snapshot, unconsolidated. The result types are named `*Vector` (`CustomerByCustkeyVector`, `OrdersByCustkeyVector`, `JoinedByCustkeyOrderkeyVector`, `LineitemByCustkeyOrderkeyVector`):

- `customers_after` returns the customers reader's after snapshot.
- `orders_before` returns the orders-by-customer reader's before snapshot.
- `lineitems_before` returns the line-items reader's before snapshot.
- `joined_orders_after` reconstructs `J⁺` for the `(customer, order)` pairs in `ΔL`. It looks each pair up in the customers' and the orders-by-order readers' after snapshots, then multiplies their signed weights.

The first three check that each requested customer was collected and hand over the reader's whole batches, which hold every row of the touched groups; the join seeks only the keys it needs. Only `J⁺` copies rows, into a transient native indexed vector. No reader builds an accumulated `J` relation, or opens a cursor on the index. An entry that two readers take is stored twice, once in each reader's shape. Decoding, projecting, and sorting are charged to Q3 maintenance. No hard memory bound is claimed.

The join readers (`join_orders_customers`, `join_lineitems_orders`) call `expect` on reader errors. A request outside the touched groups therefore panics the worker; `reconstruction::prepare` makes `Dlt` complete, so a harness-fed change never makes one.

`verify.sh` in the Q3 experiment runs both generated circuit modes over the same loading and RF1/RF2 transactions and checks reader rows, emitted deltas, and materialized `V` against a full join recomputed from the logical records. It also compares the two modes' per-transaction JSON output byte for byte. The COL weighted-reader, storage, and compaction tests stay in this library's suite.
