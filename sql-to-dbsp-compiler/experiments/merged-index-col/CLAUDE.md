# merged-index-col: Customer–Orders–Lineitem index

This standalone library supplies the concrete COL definition for DBSP's general merged-index module, `dbsp::trace::merged_index`, and the Q3 readers that the reconstructed circuit uses. Shared rules for any index and harness are in [experiments/CLAUDE.md](../CLAUDE.md); the generic readers and scan session are in [crates/dbsp/src/trace/merged_index/CLAUDE.md](../../../crates/dbsp/src/trace/merged_index/CLAUDE.md). Layout reference: [storage-layout.md](../../../docs/design/merged-index/storage-layout.md).

## Definition

The definition is generated by the SQL compiler from `col.mi` into the committed `src/generated.rs`, which the crate root re-exports: the key and payload types, `CustomerOrdersLineitemDefinition` with typed fold and unfold, the prefix functions, the `TAG_*` and `INDEX_ID_*` constants, and the payload codec. `lib.rs` adds only `build_batch`. Regenerate with `generate.sh` (rule in [experiments/CLAUDE.md](../CLAUDE.md)); do not edit `generated.rs` by hand.

Folded keys are 11, 20, and 25 bytes:

```text
domain tags:    INDEX = 0x00, custkey = 0x01, orderkey = 0x02, linenumber = 0x03
placement ids:  CustomerByCustkey = 0x01, OrdersByCustkeyOrderkey = 0x02, LineitemByCustkeyOrderkeyLinenumber = 0x03

C(c):     0x01 fold_i64(c) | INDEX | 0x01                                  (11 bytes)
O(c,o):   0x01 fold_i64(c) | 0x02 fold_i64(o) | INDEX | 0x02               (20 bytes)
L(c,o,l): 0x01 fold_i64(c) | 0x02 fold_i64(o) | 0x03 fold_i32(l) | INDEX | 0x03   (25 bytes)
```

`Key` is an enum with one variant per placement, each holding a key struct with one field per path domain:

| Placement (id) | Key struct | Payload struct |
| --- | --- | --- |
| `CustomerByCustkey` (1) | `{ custkey: i64 }` | `{ c_mktsegment: SqlString }` |
| `OrdersByCustkeyOrderkey` (2) | `{ custkey: i64, orderkey: i64 }` | `{ o_orderdate: Date, o_shippriority: i32 }` |
| `LineitemByCustkeyOrderkeyLinenumber` (3) | `{ custkey: i64, orderkey: i64, linenumber: i32 }` | `{ l_shipdate: Date, l_extendedprice: SqlDecimal<15, 2>, l_discount: SqlDecimal<4, 2> }` |

Struct names are the placement name plus `Key` or `Payload`. Prefix functions: `prefix_custkey`, `prefix_custkey_orderkey`, `prefix_custkey_orderkey_then_linenumber`, and the others the trie implies. The tests tie the constants to the trie with `check_against_trie`.

Payload rules:

- The stored value is the packed encoding of one payload as opaque bytes, with no tag; the key's index id names the placement. `decode_payload(&Key, &[u8])` dispatches on the key's variant and accepts only canonical bytes. The test `packed_payload_decoding_needs_the_matching_key` checks the fixtures' pairs, but no check guarantees a mismatch fails.
- `Payload::matches` ties a payload to its placement; `build_batch` rejects a mismatch before it encodes.
- The packed encoding is little-endian with no padding. A string is a LEB128 length and UTF-8 bytes. A decimal takes the narrowest integer for its precision (`i16` up to 4, `i32` up to 9, `i64` up to 18, else `i128`).
- This experiment does not migrate files written with an earlier payload codec (values were byte strings until 2026-10-16, the typed `SourcePayload` until 2026-10-19).

## Q3 readers (`src/q3.rs`, `src/q3/`)

The `q3` module reconstructs the four native accumulated reads from COL snapshots that the harness maintains outside the circuit. The harness's `ManualIndex` ([q3-ivm-baseline](../q3-ivm-baseline/CLAUDE.md)) appends to the index; this library never does.

- `Q3State::publish(old, dlt)` supplies a transaction's snapshots. `Q3State::collect(Pass)` captures `Dlt` and scans the touched groups once. `finish` returns `SessionReads` and releases the readers. The publication, the sealed readers, the contract check, and `SessionReads` are the generic `TransactionViews` (`dbsp::trace::merged_index::transaction`); `q3` re-exports `SessionReads`, `OwnerReads`, `OwnerExpansions`, and `SourceSnapshot`.
- The readers: `CustomersAfter` (`C⁺`), `OrdersBefore` (`O⁻`), `JoinedAfter` (`J⁺`), `LineitemsBefore` (`L⁻`). Their requests and kept rows are tabulated in [shared-traversal.md](../../../docs/design/merged-index/shared-traversal.md).
- `collect` returns a `Collection` whose `DrivingDeltas` move `ΔC`, `ΔO`, and `ΔL` out once per transaction, no clone, and seals each reader (`Reader::into_sealed`, `SealedReader`: its requests and finished partner batch, `Sync`), so the joins read the partners with no lock (user decision of 2026-11-16).
- The types are named `*Vector` (user decision of 2026-11-10).
- A partner read errors on a delta key outside its reader's requests.
- Each reader copies the rows it keeps from the index into a typed batch, its requested slice, which the existing joins read as their partner. A direct reconstructed cursor is a future optimization.
- Read owners: `collect` reads the index under `MergedIndex`; the routing's merge of the driving deltas `ΔC` and `ΔO` is under `requested_slice` on the collecting thread; `Q3State::finish` returns every owner's reads there (`driver_reads`).

### The Q3 hook

The stored readers go through the generic `route`. The Q3 hook in `q3.rs` adds the customer and order steps that compute `J`; it is the one place the generic machinery has no notion of a join. At a customer it forms the customer after (`Old` plus `ΔC`). At an order it forms `J⁺`'s rows where `ΔL` is, and `ΔJ = ΔO ⋈ C⁺ + O⁻ ⋈ ΔC` where `ΔO` or `ΔC` is, so `L⁻` requests exactly the nodes of the circuit's own `ΔJ`, orders that only `ΔO` mentions included. `ΔJ` is a request set only: the circuit computes its own. The planned generic replacement is "Generic readers" in [deferred.md](../../../docs/design/merged-index/deferred.md).

### The `expect` contract

The join readers (`join_orders_customers`, `join_lineitems_orders`) call `expect` on reader errors. A delta row whose trie keys fall outside the touched groups therefore panics the worker; the harness's `reconstruction::prepare` gives every row its keys first.

## Tests

```bash
cargo +1.96.1 test --offline --locked                     # this directory
cargo +1.96.1 test --offline -p dbsp --lib merged_index   # from the repository root
```

- `src/tests.rs`: encoding, golden bytes, payload validation, batch consolidation, cursor seeks. `src/layout_tests.rs`: layer-file layout. `src/storage_tests.rs`: file runs (keeps `Some(0)` on purpose), native spine compaction, snapshots, reopened files.
- `src/q3/tests.rs`: reader tests and the run-counter baseline, including `collect_reads_the_index_once_and_the_readers_not_at_all` and `the_passes_pass_untouched_groups_in_different_ways` (a deliberate two-run layout) that pin the two `Pass` modes' counts.
- The Q3 harness's `verify.sh` runs both modes over the same transactions and checks reader rows, emitted deltas, and materialized `V` against a full join; see [q3-ivm-baseline/CLAUDE.md](../q3-ivm-baseline/CLAUDE.md).
